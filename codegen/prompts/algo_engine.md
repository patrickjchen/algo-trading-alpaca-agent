You are generating: algo_engine.py — the STRATEGY / ALGO ENGINE service. It runs execution algorithms (TWAP today;
VWAP / IS registered as unavailable stubs in algos.py) as a standalone worker. It receives `create` / `cancel`
requests that OMS forwards on `alpaca:algo:requests`, keeps live algo state in Redis, submits every child order
THROUGH OMS (`runtime.send_command(r, runtime.STREAM_OMS_COMMANDS, …)` with `source: "algo"`), tracks children via
OMS's live order hashes, and emits snapshots to `alpaca:algo:events` for the persister. It NEVER calls Alpaca order
endpoints and NEVER writes SQLite (one read-only cold-start reload is allowed). Pure math comes from algos.py
(`algos.REGISTRY`, `algos.build_schedule`, `Strategy.child_price`, `algos.rules_from_dict`, `round_qty/round_price`).

LIVE STATE (keys from runtime: `algo_key`, `algo_slices_key`, `SET_ACTIVE_ALGOS`, `STATE_TTL_S`; values via `runtime.hset_state`)
- algo hash fields: `algo_id, strategy, account, book, symbol, side, total_qty, n_slices, start_ts, end_ts, limit_cap, params_json, source, status, filled_qty, avg_px, error, created_at, updated_at` (ISO timestamps; floats as str).
- slices hash: field `str(slice_idx)` → JSON `{algo_id, slice_idx, scheduled_ts, qty, client_order_id, order_id, limit_price, status, filled_qty, updated_at}`.
- Statuses: algo `pending|running|completed|partial|cancelled|failed`; slice `scheduled|submitted|working|filled|rolled|cancelled|failed`.
- Helpers: `load_algo(r, algo_id) -> dict | None` (typed), `load_slices(r, algo_id) -> list[dict]` (sorted), `save_algo(r, algo: dict, *, emit=True)` (hset_state + `publish(STREAM_ALGO_EVENTS, {type:"algo", ts, algo})`; when the algo is terminal: EXPIRE both keys with STATE_TTL_S and SREM from SET_ACTIVE_ALGOS, else SADD), `save_slice(r, slice: dict, *, emit=True)` (HSET field + `publish({type:"slice", ts, algo_id, slice})`).
- `child_state(r, client_order_id) -> dict | None`: an intent can have TWO records — the internal one at `runtime.order_key(runtime.internal_order_id(coid))` (crossed fills, venue internal) and the exchange one at `runtime.order_key(r.get(runtime.coid_key(coid)))` when that id does not start with `int-`. Return None when neither exists; else a typed dict: `order_id` = exchange id if present else the internal id, `filled_qty` = sum of both, `filled_avg_price` = qty-weighted over both, `status` = exchange status when the exchange record exists, else the internal status mapped: `accepted`/`partially_filled` → active (working), `filled` → `filled`, `replaced` (routed, exchange record not yet visible) → `accepted`, `canceled`/`rejected` → themselves; plus `internal_filled_qty`, `external_filled_qty` for logging.

REQUESTS
- `handle_request(r, payload: dict) -> dict` (replies with `runtime.send_reply(r, payload["cmd_id"], reply)` when r given; returns the reply):
  * `create`: validate `strategy` in `algos.REGISTRY` and available (else `ok False, error` with the stub's note), side buy|sell, total_qty>0, `n_slices` int ≥1 (default 5), `duration_s` ≥ 10*n_slices (default 300), account paper|live. `rules = algos.rules_from_dict(trader.get_asset_rules(symbol, live, r=r))` (any exception → rules with Nones, log). `start = utc_ts()+2`, `end = start+duration_s`, `slices = algos.build_schedule(...)` (ValueError → ok False). `algo_id = runtime.new_id()`; slice `client_order_id = f"algo-{algo_id[:12]}-{idx:03d}"`, status `scheduled`. `save_algo` (status pending; emit ONE event of `type:"algo"` that also includes `slices: [...]`) and HSET all slices (no per-slice events on create). Reply `{ok True, status:"pending", algo_id, algo}`.
  * `cancel`: algo unknown → `{ok False, status:"not_found"}`; already terminal → `{ok True, status: current}`; else for each slice `submitted|working` → `cancel_child(r, algo, slice)` (OMS cancel command by client_order_id; mark slice `cancelled` on `cancel_requested`/`not_found`); `scheduled` → `cancelled`; algo → `cancelled`; `save_algo`; reply `{ok True, status:"cancelled", algo_id, algo}`.
  * unknown kind → ok False.
- `submit_child(r, algo, slice, px, tif) -> dict`: `runtime.send_command(r, runtime.STREAM_OMS_COMMANDS, {kind:"submit", account, client_order_id: slice id, symbol, side, type:"limit", qty, limit_price: px, tif, source:"algo", book: algo["book"], algo_id, slice_idx}, timeout=10)`. (The algo hash and the `create` payload carry `book`, default `runtime.DEFAULT_BOOK`; store it in the algo hash and the `type:"algo"` event.) `cancel_child(r, algo, slice) -> dict`: `{kind:"cancel", account, client_order_id, source:"algo"}` likewise. Both are the ONLY places that talk to OMS (tests patch `runtime.send_command`).

ENGINE
- `refresh(r, algo: dict, slices: list[dict]) -> None`: for each slice with a client_order_id and status in `submitted|working|rolled`: `st = child_state(...)`; if st: `order_id`, `filled_qty`; status → `filled` if order status filled; `working` if active; `failed` if rejected/expired; `rolled`/`cancelled` keep their status when the order is canceled (we asked for it); emit `save_slice` only when something changed. Algo `filled_qty = Σ slice filled_qty`, `avg_px` = qty-weighted mean of each child's `filled_avg_price` (from the order hashes) over slices with fills. A slice `submitted` whose child state is still missing after 120 s → `failed` with error "child never acknowledged" (OMS reconciliation normally resolves it within 30 s; do not call Alpaca here).
- `tick(r, now_ts: float | None = None, allow_submit: bool = True) -> int`: for each `algo_id` in `SMEMBERS SET_ACTIVE_ALGOS` (skip unknown ids and SREM them): load, `refresh`; pending and now ≥ first scheduled_ts → running; for each `scheduled` slice with `scheduled_ts ≤ now` (only when `allow_submit`): roll forward = for earlier slices `working|submitted`, `cancel_child` → mark `rolled`, add `(qty - filled_qty)` to this slice (persist); `quote = trader.latest_quote(symbol, r=r)` (Redis-backed), `px = strategy.child_price(side, quote, limit_cap, final=(idx == last), rules)`; `rep = submit_child(r, algo, slice, px, "ioc" if final else "gtc")`: acked/already_submitted → slice `submitted` (+order_id from `rep["order"]`), rejected/error → slice `failed`, algo `failed` (error text; stop); unknown/timeout → leave `submitted` (refresh resolves). Finalise when every slice is terminal: `completed` if filled ≥ total*(1-1e-9), `partial` if any fill, else `failed`; if the final IOC slice is still `submitted|working` after `end_ts + 5` → cancel it and finalise `partial`/`failed`. `save_algo` on every status/filled change. One algo's exception never kills the loop: catch, log, mark that algo `failed`. Return the number of algos touched.
- `reload_from_db(r, db_path: str | None = None) -> int`: cold start only — if `SCARD SET_ACTIVE_ALGOS == 0` and the SQLite file exists: `conn = runtime.sqlite_connect(db_path)` read-only use; `SELECT * FROM algo_orders WHERE status IN ('pending','running')` + their `algo_slices` → rebuild the Redis hashes (no events); close; return count. Any exception → log, return 0.
- `process_requests(r, reader) -> int`: batch read; try → handle → ack; except → dead_letter + error reply.
- `body()`: `r = runtime.get_redis()`; `reload_from_db(r)`; `GroupReader(r, STREAM_ALGO_REQUESTS, "algo_engine", env ALGO_CONSUMER default "algo-1", block_ms=500)`; loop: `process_requests`; `oms_up = runtime.worker_alive(r, "oms") is not None` (warn once per 30 s when down); `tick(r, allow_submit=oms_up)`; sleep so the loop runs about once per second.
- `main()`: `runtime.run_forever(body, "algo_engine")`; `if __name__ == "__main__": main()`.
Restart safety: everything the engine needs is in the Redis hashes (or reloadable from SQLite); on restart `tick` simply resumes. Call `mcp__verify__verify_stage(stage="algo_engine")`.
